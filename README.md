# Monzo Bot · unofficial React Native companion

Independent, open-source transaction and budgeting companion. Not affiliated with or endorsed by Monzo Bank.

The application is now **React Native 0.88.1 + React 19.3 + TypeScript**. The Java Android interface has been replaced. Financial calculations, planning, Google export parsing, AI tools and all screens live in TypeScript. Kotlin supplies Android secure storage, fixed-origin HTTPS, Google authorization, on-device speech, private notifications and optional OS handoffs.

## Version and release status

This source identifies as **0.5.0-alpha.1**, Android build **501**. It is an experimental source prerelease, not a production app-store release. See [changelog](CHANGELOG.md) and [versioning/release gates](docs/VERSIONING.md). ## Run on your Android phone from Windows

1. Preserve any unpublished changes in your existing checkout before pulling `main`. Then install Node 24.x >=24.3 (or Node 22.x >=22.13; Node 26+ also matches the dependency engine), JDK21 and the Android SDK required by `android/build.gradle`.
2. Run `npm ci` from the repository root.
3. Connect your Pixel with USB debugging authorized. Start Metro with `npm start` in one terminal.
4. In another terminal, run `npm run android`. You can also open `android/` in Android Studio and run the app while Metro is running.

**Keep the original signing identity and app data.** The Android application ID remains `org.monzobot.app`; current versionCode is 501. Debug builds reuse an already-existing original-machine `%USERPROFILE%\.android\debug.keystore` if present. No replacement debug key is generated by this project. Alternatively configure the original private keystore with `monzoSigningStoreFile`, `monzoSigningStorePassword`, `monzoSigningKeyAlias` and `monzoSigningKeyPassword` in your private user Gradle properties. Release builds are unsigned without explicit original-keystore properties. Never commit those properties or a keystore. If a signature mismatch occurs, stop; do not uninstall or clear the existing app.

Google read-only OAuth must be configured for this package and the **actual signing certificate** in the dedicated Google Cloud project, with Drive and Sheets APIs enabled. This source does not embed a personal spreadsheet ID, token, client secret or financial export. Live Google/device acceptance remains a separate check.

## What it does

- Home insights and searchable, virtualized **whole transaction history**, preserving original export emojis, original currency evidence, notes and stable IDs. Budget dates never filter the imported history.
- Connect Google, discover native spreadsheets without entering a URL, explicitly choose a match, and read all compatible transaction tabs/rows. Multiple/no-match states are explicit; changed existing transaction IDs fail for reconciliation. GBP account currency and UK spreadsheet locale are required. Each tab is bounded at 50,000 rows/26 columns; merged local history is bounded at 100,000 transactions. No partial response is silently saved.
- CSV and plaintext workspace JSON import (stored encrypted on-device); deliberate plaintext export through the Android document picker. Source rows are never written back to Google.
- Category emojis/corrections, exact integer-pence budgets, essential priorities, a dated user-reported cash balance, reserve and explicit commitments.
- Tentative purchase plans from offline rules or separately approved OpenAI/Anthropic AI extraction. Editable fields, deterministic impact/freshness/source review and explicit confirmation are mandatory. Model-created figures/actions are rejected; duplicate submission cannot add a provision twice.
- Optional BYOK Ask with editable per-provider models, isolated optional saved keys, named processing consent and separate label-sharing consent. Bounded local read-only tools support spending, budget impact and payment-review candidates. No automatic payment, borrowing, creditor contact or budget mutation.
- On-device voice where Android supports it; editable transcript and honest typing fallback. Calendar and notes handoffs each require a separate preview/approval; amounts start excluded.
- Private on-device check-ins with Android permission/channel controls, quiet hours, cooldowns, daily caps and optional quiet persistent status. Background checks inspect the stored export; they do **not** fetch live bank data or invoke AI. Refresh Google inside the app. OS restrictions can delay delivery.

## Local bill review

Home now offers an off-by-default local bill-analysis permission. Review equal-amount weekly/monthly candidates against their transaction evidence, edit the amount/date, and explicitly confirm a local plan commitment. No bank action, AI call, sharing or reminder is performed. Variable or irregular bills may be missed; a refreshed export still does not establish complete coverage. Revocation leaves previously confirmed commitments unchanged. Restoring a backup requires a fresh scan opt-in.

See [financial assistant direction and integration boundaries](docs/ASSISTANT_DIRECTION.md) for researched alternatives and why the personal Monzo Developer API is not a general public integration solution.

## Verification and limits

Run `npm run typecheck`, `npm test -- --runInBand`, and `npm run lint`. Android native checks use `android/gradlew testDebugUnitTest lintDebug`; an unsigned release build can validate packaging without changing signing identity. All committed fixtures/tests are synthetic; transport tests use fake responses and keys.

The React Native UI/domain are shared-platform code. Android secure/device adapters are implemented. The iOS project is a scaffold: its secure storage, Google, voice and notification adapters still need implementing and testing. There is no claim that iOS, desktop or web already work.

Successful retrieval does not prove complete bank coverage, available cash or future payments. The app shows retrieval freshness and observed transaction cutoff; suspected duplicate/recurring/anomalous payments are review candidates, not verified fraud or bills. A matching-signature Android update was installed and launched on 16 November 2026, retaining existing records; the bill-review opt-in, evidence form, Back cancellation and revocation were checked. This was the earlier build 400 at commit 42c0b16, not acceptance of every later change. The AI privacy notice has synthetic UI tests and production-bundle validation, not live-provider or device acceptance. Full migration/backup/lifecycle, notification delivery, Google consent and speech remain separate acceptance checks.

See [privacy](docs/PRIVACY.md), [migration](docs/MIGRATION.md) and [AI boundaries](docs/AI.md).

## Data-source requirements

Android 11/API 30+ is the effective app minimum. SDK build-tools 37.0.0, compile SDK 37, target SDK 36 and NDK 27.1.12297006 are configured. Node 24.13/JDK21 were used for local validation. iOS remains a scaffold even though version metadata is aligned.

[Monzo manual exports](https://monzo.com/help/budgeting-overdrafts-savings/exporting-my-transactions) support date-ranged CSV; the help page states no paid-plan prerequisite. Basic-account eligibility and a real exported CSV have not been device-tested here. The optional [Google Sheets auto-export route](https://monzo.com/help/monzo-extra/advanced-budgeting-auto-exports) is a paid-plan feature. This app is not a live bank connection.

**CSV import replaces the active transaction set; it does not append files or establish complete coverage.** Select a complete intended date range and preserve an export before replacement. The parser requires supported Monzo headers, GBP account currency and stable IDs; conflicting duplicate IDs fail. Plans remain local and need reconciliation after source changes.

# Monzo Bot · unofficial React Native companion

Independent, open-source transaction and budgeting companion. Not affiliated with or endorsed by Monzo Bank.

The application is now **React Native 0.88.1 + React 19.3 + TypeScript**. The Java Android interface has been replaced. Financial calculations, planning, Google export parsing, AI tools and all screens live in TypeScript. Kotlin supplies Android secure storage, fixed-origin HTTPS, Google authorization, on-device speech, private notifications and optional OS handoffs.

## Run on your Android phone from Windows

1. Preserve any unpublished changes in your existing checkout before pulling `main`. Then install Node 24.3+ (or a supported Node 22 release), JDK21 and the Android SDK required by `android/build.gradle`.
2. Run `npm ci` from the repository root.
3. Connect your Pixel with USB debugging authorized. Start Metro with `npm start` in one terminal.
4. In another terminal, run `npm run android`. You can also open `android/` in Android Studio and run the app while Metro is running.

**Keep the original signing identity and app data.** The Android application ID remains `org.monzobot.app`; versionCode is400. Debug builds reuse an already-existing original-machine `%USERPROFILE%\.android\debug.keystore` if present. No replacement debug key is generated by this project. Alternatively configure the original private keystore with `monzoSigningStoreFile`, `monzoSigningStorePassword`, `monzoSigningKeyAlias` and `monzoSigningKeyPassword` in your private user Gradle properties. Release builds are unsigned without explicit original-keystore properties. Never commit those properties or a keystore. If a signature mismatch occurs, stop; do not uninstall or clear the existing app.

Google read-only OAuth must be configured for this package and the **actual signing certificate** in the dedicated Google Cloud project, with Drive and Sheets APIs enabled. This source does not embed a personal spreadsheet ID, token, client secret or financial export. Live Google/device acceptance remains a separate check.

## What it does

- Home insights and searchable, virtualized **whole transaction history**, preserving original export emojis, original currency evidence, notes and stable IDs. Budget dates never filter the imported history.
- Connect Google, discover native spreadsheets without entering a URL, explicitly choose a match, and read all compatible transaction tabs/rows. Multiple/no-match states are explicit; changed existing transaction IDs fail for reconciliation. GBP account currency and UK spreadsheet locale are required. Each tab is bounded at50,000rows/26columns; merged local history is bounded at100,000transactions. No partial response is silently saved.
- CSV and encrypted-workspace JSON migration/import; deliberate plaintext export through the Android document picker. Source rows are never written back to Google.
- Category emojis/corrections, exact integer-pence budgets, essential priorities, a dated user-reported cash balance, reserve and explicit commitments.
- Tentative purchase plans from offline rules or separately approved OpenAI/Anthropic AI extraction. Editable fields, deterministic impact/freshness/source review and explicit confirmation are mandatory. Model-created figures/actions are rejected; duplicate submission cannot add a provision twice.
- Optional BYOK Ask with editable per-provider models, isolated optional saved keys, named processing consent and separate label-sharing consent. Bounded local read-only tools support spending, budget impact and payment-review candidates. No automatic payment, borrowing, creditor contact or budget mutation.
- On-device voice where Android supports it; editable transcript and honest typing fallback. Calendar and notes handoffs each require a separate preview/approval; amounts start excluded.
- Private on-device check-ins with Android permission/channel controls, quiet hours, cooldowns, daily caps and optional quiet persistent status. Background checks inspect the stored export; they do **not** fetch live bank data or invoke AI. Refresh Google inside the app. OS restrictions can delay delivery.

## Verification and limits

Run `npm run typecheck`, `npm test -- --runInBand`, and `npm run lint`. Android native checks use `android/gradlew testDebugUnitTest lintDebug`; an unsigned release build can validate packaging without changing signing identity. All committed fixtures/tests are synthetic; transport tests use fake responses and keys.

The React Native UI/domain are shared-platform code. Android secure/device adapters are implemented. The iOS project is a scaffold: its secure storage, Google, voice and notification adapters still need implementing and testing. There is no claim that iOS, desktop or web already work.

Successful retrieval does not prove complete bank coverage, available cash or future payments. The app shows retrieval freshness and observed transaction cutoff; suspected duplicate/recurring/anomalous payments are review candidates, not verified fraud or bills. Live provider/model availability, real Android Keystore migration, notification delivery, Google consent, speech and the original signed Pixel update require device/service acceptance.
